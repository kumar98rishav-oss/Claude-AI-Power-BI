Gateway and refresh

Trainer demo

Everyone understands why the Service needs a gateway for Meridian, and sees Claude read the refresh history.

Meridian reads CSV files from a folder on your laptop. The Service can't reach your C: drive, so a scheduled refresh in the Service fails until a gateway connects them.

Personal mode gateway

You install it yourself. One per user, Power BI only, Import models only. Refresh works only while your laptop is on. Fine for training.

Standard gateway

Installed by IT on an always-on server, shared by many people. What production uses, and what we'll point at SQL Server in a later session.

Steps (on your screen)

  1. Show the gateway in the Service: semantic model › Settings › Gateway and cloud connections. Map the CSV data source to the gateway, enter its credentials, and turn on scheduled refresh (for example daily, 07:00).

    Say"The daily refresh belongs to Power BI, not to Claude. It's free and reliable. Claude's job is to check that it worked."

  2. Ask Claude to read the refresh history through the service-check script.

    In Claude
    Run .claude/skills/service-check/scripts/service_check.ps1 with my workspace ID and model ID, and tell me if the last refresh worked and whether the data source goes through a gateway.

    The script signs you in to Power BI in the browser the first time, then reads the refresh history and data sources through the Power BI REST API. It changes nothing. Reading refresh history needs Write permission on the model.

  3. Optional: start a refresh on purpose with the /refresh-now Skill (it asks before doing anything), then run the check again.

CheckThe history shows your scheduled or on-demand refresh as Completed, and the data source shows a gateway.
If it failsA failed refresh with a gateway or credentials error: the gateway is offline (is the laptop on?) or the data source credentials aren't set. On shared capacity the API allows about 8 refresh requests a day.

  2. Option 3: run a Skill without anyone at the keyboard.

    run-snapshot.cmd

echo ===== %DATE% %TIME% ===== >> logs\snapshot.log
claude -p "/report-snapshot" --allowedTools "mcp__powerbi-modeling__*" "Bash(python *)" --max-turns 30 >> logs\snapshot.log 2>&1

    Terminal (CMD or PowerShell)
    schtasks /Create /TN "Meridian report snapshot" /SC WEEKLY /D MON,TUE,WED,THU,FRI /ST 09:00 /TR "C:\Training\pbip-project\run-snapshot.cmd"

    schtasks /Run /TN "Meridian report snapshot"

# Service check (read-only)

Checks the **published** model, the same way every time. Never changes anything.

## Settings (edit for your workspace)

- Workspace name: `Data Analysis_dev`
- Workspace ID: `<paste from the URL: app.powerbi.com/groups/<workspace-id>/...>`
- Semantic model name: `MeridianSupplyChain`
- Semantic model ID: `<paste from the URL: .../datasets/<model-id>/details>`

## Rules

- Read only. Never create, change, refresh, publish or delete anything.
- Totals and lists only, never row-level data.
- If a step fails, say why in one line and carry on.

## Steps

1. **Connect** with the Power BI modeling MCP server:
   `Connect to semantic model 'MeridianSupplyChain' in Fabric Workspace 'Data Analysis_dev'`
2. **Last refresh (model side):** run
   `EVALUATE SELECTCOLUMNS ( INFO.PARTITIONS (), "Table", [Name], "RefreshedTime", [RefreshedTime] )`
   Report the newest time (UTC and local). Ignore `_Measures`.
3. **Refresh history, data sources and gateway (service side):** run
   `powershell -NoProfile -ExecutionPolicy Bypass -File .claude/skills/service-check/scripts/service_check.ps1 -WorkspaceId <id> -DatasetId <id>`
   Show the last 5 refreshes (type, status, start, duration) and the error text of any failure. List each data source and whether it goes through a gateway.
4. **Key KPIs:** run the KPI query from the report-snapshot Skill (latest year vs previous) and apply its threshold table.

## Output

Four headings in this order: **Connection**, **Refresh**, **Data sources and gateway**, **KPIs**. End with **Flags**: any failed refresh, a refresh older than 24 hours, a data source without a gateway, any KPI threshold break. Or "No flags today."
.claude/skills/service-check/scripts/service_check.ps1
# Read-only: refresh history, data sources and gateway status of a published semantic model.
# Usage: powershell -NoProfile -ExecutionPolicy Bypass -File service_check.ps1 -WorkspaceId <guid> -DatasetId <guid> [-Top 5]
# Needs: Install-Module MicrosoftPowerBIMgmt -Scope CurrentUser   (one time)
param(
    [Parameter(Mandatory = $true)][string]$WorkspaceId,
    [Parameter(Mandatory = $true)][string]$DatasetId,
    [int]$Top = 5
)
$ErrorActionPreference = 'Stop'

if (-not (Get-Module -ListAvailable -Name MicrosoftPowerBIMgmt.Profile)) {
    Write-Output "MicrosoftPowerBIMgmt is not installed. Run: Install-Module MicrosoftPowerBIMgmt -Scope CurrentUser"
    exit 1
}
Import-Module MicrosoftPowerBIMgmt.Profile

# Reuse an existing sign-in if there is one; otherwise open the browser sign-in.
try { $null = Get-PowerBIAccessToken } catch { Connect-PowerBIServiceAccount | Out-Null }

$base = "groups/$WorkspaceId/datasets/$DatasetId"

Write-Output "== Refresh history (last $Top) =="
try {
    $refreshes = (Invoke-PowerBIRestMethod -Url "$base/refreshes?`$top=$Top" -Method Get | ConvertFrom-Json).value
    foreach ($r in $refreshes) {
        $mins = if ($r.endTime) { [math]::Round(((Get-Date $r.endTime) - (Get-Date $r.startTime)).TotalMinutes, 1) } else { 'running' }
        Write-Output ("{0,-10} {1,-10} start {2}  minutes {3}" -f $r.refreshType, $r.status, $r.startTime, $mins)
        if ($r.status -eq 'Failed' -and $r.serviceExceptionJson) { Write-Output "    error: $($r.serviceExceptionJson)" }
    }
} catch { Write-Output "Could not read refresh history (you need Write permission on the model): $($_.Exception.Message)" }

Write-Output ""
Write-Output "== Data sources =="
try {
    $sources = (Invoke-PowerBIRestMethod -Url "$base/datasources" -Method Get | ConvertFrom-Json).value
    foreach ($s in $sources) {
        $gw = if ($s.gatewayId) { "gateway $($s.gatewayId)" } else { 'no gateway' }
        Write-Output ("{0,-12} {1}  ({2})" -f $s.datasourceType, ($s.connectionDetails | ConvertTo-Json -Compress), $gw)
        if ($s.gatewayId -and $s.datasourceId) {
            try {
                Invoke-PowerBIRestMethod -Url "gateways/$($s.gatewayId)/datasources/$($s.datasourceId)/status" -Method Get | Out-Null
                Write-Output "    gateway status: OK"
            } catch { Write-Output "    gateway status: could not check ($($_.Exception.Message))" }
        }
    }
} catch { Write-Output "Could not read data sources: $($_.Exception.Message)" }

Use when asked to change, format or fix a paginated report or an .rdl file, or when Report Builder shows a "Deserialization failed" error.

# Paginated report (.rdl) editor

An .rdl file is XML in the RDL 2016 schema (`http://schemas.microsoft.com/sqlserver/reporting/2016/01/reportdefinition`). Report Builder refuses the whole file if one element is wrong, so follow these rules exactly.

## Rules

- **Never touch the data source or dataset connection.** Create those in Report Builder (Power BI semantic model connection). Only change layout, formatting, parameters and expressions.
- **Back up first:** copy `<name>.rdl` to `<name>.backup.rdl` before the first edit.
- **Use only elements the schema allows.** Borders are written with a `<Border>` element inside `<Style>`, never `<BorderStyle>`:

  ```xml
  <Style>
    <Border>
      <Color>#cfd4da</Color>
      <Style>Solid</Style>
      <Width>1pt</Width>
    </Border>
  </Style>
  ```

  Allowed children of `<Style>` include Border, TopBorder, BottomBorder, LeftBorder, RightBorder, BackgroundColor, FontStyle, FontFamily, FontSize, FontWeight, Format, TextDecoration, TextAlign, VerticalAlign, Color, PaddingLeft, PaddingRight, PaddingTop, PaddingBottom (from Report Builder's own error message).
- Element names are case-sensitive. Keep every element in the order Report Builder wrote it. Don't invent elements.
- Field references use the dataset's field names exactly, e.g. `=Fields!Supplier.Value`.

## Steps

1. Read the .rdl and list what's in it: data sources, datasets and their fields, parameters, the body items.
2. Make a backup copy.
3. Make the requested change, following the rules.
4. Check: the file is well-formed XML, every `<Style>` child is in the allowed list, and every `Fields!X` exists in the dataset.
5. Tell the user what changed, and to reopen the file in Report Builder. If Report Builder shows an error, ask them to paste it: the message names the bad element, the expected elements, and the line and position.

## Never

- Publish, render or export the report. That happens in Report Builder or the Power BI service.
- Put credentials or connection strings in the file.

# Refresh now (changes the service: run only on request)

`disable-model-invocation: true` means Claude never runs this on its own. You must type `/refresh-now`.

## Settings

- Workspace ID: `<workspace-id>`
- Semantic model ID: `<model-id>`

## Steps

1. Ask the user to confirm: "Start a refresh of MeridianSupplyChain in the service now?" Stop unless they say yes.
2. Start the refresh:
   `powershell -NoProfile -ExecutionPolicy Bypass -File .claude/skills/refresh-now/scripts/refresh_now.ps1 -WorkspaceId <workspace-id> -DatasetId <model-id>`
3. Wait about a minute, then run `.claude/skills/service-check/scripts/service_check.ps1` (same IDs) to read the latest refresh status. Repeat up to 5 times until the status is Completed or Failed.
4. Report: status, how long it took, and the error text if it failed. If the error mentions a gateway or credentials, say: "check the gateway is running and the data source credentials in the semantic model's settings".

## Notes

- On shared (non-Premium) capacity, the API allows about 8 refresh requests per day.
- Power BI's own **scheduled refresh** is the right tool for daily refreshes. Use this Skill only for "refresh it now".
.claude/skills/refresh-now/scripts/refresh_now.ps1
# Starts an on-demand refresh of a published semantic model (this CHANGES the service).
# Usage: powershell -NoProfile -ExecutionPolicy Bypass -File refresh_now.ps1 -WorkspaceId <guid> -DatasetId <guid>
param(
    [Parameter(Mandatory = $true)][string]$WorkspaceId,
    [Parameter(Mandatory = $true)][string]$DatasetId
)
