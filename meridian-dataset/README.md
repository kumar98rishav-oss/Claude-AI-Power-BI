# Meridian Medical Supply: the training dataset

One fictional company, used in every session of the Claude + Power BI programme. **Meridian Medical Supply** distributes medical consumables (PPE, wound care, diagnostics, infusion, surgical supplies, mobility aids) from 5 US distribution centres to 150 hospitals, clinics, pharmacies and care homes. It covers two calendar years, **January 2024 to December 2025**. The fiscal year starts on **1 July**, so FY2025 runs from Jul 2024 to Jun 2025.

The data is generated by `generate_dataset.py` with a fixed seed, so it is identical every time. It contains **planted stories** that participants can find, and **deliberate defects** in a separate copy for the data-quality and reconciliation sessions.

## What is in this folder

| Path | What it is |
| --- | --- |
| `data/` | The clean CSVs: 6 dimensions and 3 facts, UTF-8, ISO dates |
| `data_quality_lab/` | A copy of `Fact_Sales` and `Dim_Customer` with 8 planted defects, listed in `ISSUES.csv` |
| `pbip/MeridianSupplyChain.pbip` | The Power BI project: a TMDL semantic model and a 3-page PBIR report, saved by Power BI Desktop |
| `sql/01_create_and_load.sql` | Creates the `MeridianSupplyChain` database on SQL Server and loads the CSVs |
| `docs/screenshots/` | The three report pages, captured from Power BI Desktop |
| `generate_dataset.py` | Rebuilds `data/` and `data_quality_lab/` |
| `build_pbip.py` | Rebuilt the PBIP from scratch. Desktop has saved the project since, so re-run it only to start over |
| `verify_stories.py` | Prints the figures behind each planted story |

## Get it running

1. **Power BI:** open `pbip/MeridianSupplyChain.pbip`. Then go to **Transform data → Edit parameters** and set `DataFolder` to the full path of `data\`, ending in a backslash. Refresh.
2. **SQL Server (for the reconciliation sessions):**

   ```
   sqlcmd -S localhost\SQLEXPRESS -E -C -i sql\01_create_and_load.sql -v DataFolder="C:\full\path\to\data"
   ```

   The script ends by printing row counts and totals. They must match the Power BI model: **18,470 sales lines, $26,974,377.45 revenue.**

## The model

Three fact tables share conformed dimensions. Two features are there on purpose to teach from: **role-playing dates** (one active relationship per fact, the others inactive) and a **snowflake** from product to supplier.

| Table | Rows | Grain and purpose |
| --- | ---: | --- |
| `Fact_Sales` | 18,470 | One row per sales order line. Order, requested, ship and delivery dates; quantity, price, discount, amount, cost |
| `Fact_Purchases` | 2,073 | One row per purchase order line. Order, promised and received dates; quantity ordered and received |
| `Fact_Inventory` | 7,200 | Month-end stock per product and warehouse (24 months × 60 × 5). **Semi-additive:** never sum across dates |
| `Dim_Date` | 731 | One row per day, with calendar and fiscal columns. Marked as the date table |
| `Dim_Product` | 60 | SKU, name, category, subcategory, supplier, unit cost, list price, status (2 discontinued) |
| `Dim_Supplier` | 12 | Supplier, country, standard lead time, payment terms, tier |
| `Dim_Warehouse` | 5 | Atlanta, Dallas, Chicago, Newark, Reno. One region each |
| `Dim_Customer` | 150 | Name, type, city, state, region, customer since |
| `Dim_Carrier` | 4 | Swift Freight, BlueLine Express, Continental LTL, Metro Courier |

**Relationships (15).** `Fact_Sales` links to Date (by OrderDate; ShipDate is inactive), Customer, Product, Warehouse and Carrier. `Fact_Purchases` links to Date (by OrderDate; PromisedDate and ReceivedDate are inactive), Product and Warehouse. `Fact_Inventory` links to Date, Product and Warehouse. `Dim_Product` links to `Dim_Supplier`.

`Fact_Purchases.SupplierKey` has **no** relationship, on purpose. A second path to `Dim_Supplier` would make the model ambiguous. Ask participants why.

**Also in the model:**
- 30 measures in 5 display folders: Sales, Time Intelligence, Delivery, Procurement, Inventory.
- A `DataFolder` parameter (in `expressions.tmdl`).
- A calculated column (`Fact_Purchases[Days Late]`).
- Three hierarchies (Calendar, Product Hierarchy, Network).
- A static RLS role, `West Region`.

## Data quality lab

`data_quality_lab/` holds the same `Fact_Sales` and `Dim_Customer` with these defects. Load it in place of `data/` for the cleansing and reconciliation sessions.

| Table | Defect | How to detect |
| --- | --- | --- |
| Fact_Sales | 3 rows with ProductKey 999 (orphan) | Left join to Dim_Product |
| Fact_Sales | 2 duplicated order lines | Group by SalesLineKey, count > 1 |
| Fact_Sales | 1 negative quantity with no return flag | Quantity < 0 |
| Fact_Sales | 4 blank CustomerKeys | CustomerKey is null |
| Fact_Sales | DiscountPct stored as text ('5%') | Power Query type-change error |
| Fact_Sales | 3 dates written as MM/DD/YYYY | Power Query date parse errors |
| Dim_Customer | Region in lower case, trailing and leading spaces | Distinct Region shows extra values |
| Dim_Customer | Duplicate CustomerKey 61 | Breaks the one-to-many relationship on load |
